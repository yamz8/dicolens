# Translations

Dicolens follows the language picked under Omarchy's **Setup > Language**: English plus Omarchy's 49 translations. Each language has a catalog, `src/i18n/<code>.json`, a flat JSON object from English source text to its translation, compiled into the binary through `src/resources.qrc`. A counted string, `qsTr("%Ln images", "", count)`, maps to an object of plural forms keyed by CLDR category (`{"one": "%Ln image", "other": "%Ln images"}`), and each language gives exactly the categories its counts reach, by the rules in `Translator::pluralCategory`. A string a catalog doesn't have yet shows in English (a regional catalog such as `pt-BR` falls back to `pt` first).

## Adding or changing a string

Changes only ever touch English: wrap the text in `qsTr()` (QML) or `tr()` (C++), and add it to `src/i18n/en.json` as itself, or with its `one` and `other` forms when it's counted. The `englishCatalogListsEveryString` test keeps `en.json` exactly in step with the sources. Leave the other catalogs alone. Since the English is the key, rewording a string makes a new key; its translations become pending, and the old key is dropped by the next sync. The catalog tests check the translations that are there (placeholders, plural forms, every catalog listed in `resources.qrc`), but never require them to be complete, so English is never blocked.

## Keeping translations in sync

The `Sync translations` workflow (`.github/workflows/i18n-sync.yml`) does the converging, the way Omarchy's and Folio's do. It runs on pushes to `main` that change `src/i18n/en.json`, daily, and on demand. `scripts/i18n-sync.py pending` lists, per language, the strings that are missing or whose translation no longer fits (a broken placeholder, the wrong plural forms), and the keys `en.json` no longer has. Then:

1. One runner per pending language, holding only the Muse key and no repository credentials, runs `translate --locale <code>`. Muse only returns text: the script validates every value and writes that one catalog, dropping keys English no longer has. Whatever fails stays pending.
2. A collect job, with no credentials, takes from each runner only its own `<code>.json`, keeps its current and valid entries, and runs the catalog tests against the result in an Arch container.
3. A land job, holding the `I18N_SYNC_TOKEN`, runs no repository code: it checks that the collected patch touches nothing but language catalogs (never `en.json`), commits it to the `i18n-sync` branch, and opens and merges an `Update translations` pull request. The next run rebuilds that branch from `main`, so a sync pull request is never left open.

A language that failed, or a run that broke, just leaves strings pending for the next run. The same script works locally: `python3 scripts/i18n-sync.py pending` shows the queue, and `translate --locale da` fills one language with a local Muse.

Repository settings this needs (until they are set, the workflow's translate jobs fail and nothing lands):

- `MUSE_API_KEY`, an Actions secret for the translation runners.
- `I18N_SYNC_TOKEN`, an Actions secret holding a fine-grained PAT with Contents and Pull requests read and write on this repository, for the bot that opens and merges the sync pull request.
- Optionally `MUSE_MODEL`, an Actions variable naming the Muse model (default `muse-spark-1.3-contributor`).

## Translator brief

The brief Muse gets lives in `scripts/i18n-sync.py` (`BRIEF`); it applies to people translating by hand too. Write like the interface was made in the language: short, natural, the register of consumer desktop software, with the words a radiology department in that language really uses (slice, series, study, window, axial, coronal, sagittal, slab, uptake); where clinicians say the English or Latin term, keep it. Keep exactly: product names (Dicolens, Omarchy, ffmpeg, bsdtar), the names of formats and techniques (DICOM, CT, MR, PET, PDF, MIP, MinIP, SUV, HU, 3D, Cobb), units (mm, cm, px), key names and symbols (Ctrl, Shift, Tab, Esc, ←, →), the letters at an image's edges (R, L, A, P, H, F), and placeholders: `%1` to `%9` and `%Ln` must all be there, though they may be reordered. In a plural entry, `other` keeps every placeholder, and another form may drop `%Ln` only where the language says that number with a word. Nothing in Dicolens is a diagnosis, and no translation may make it read like one. `pt` is European Portuguese and `pt-BR` Brazilian; `sr` is Serbian in Cyrillic.
